# TaskFlow - Supabase PostgreSQL & Deployment Guide

## 1. Quick Start
TaskFlow is designed to work out-of-the-box with an integrated persistent storage engine. To connect to your cloud Supabase database, follow the steps below.

---

## 2. Supabase PostgreSQL Setup

### Step 1: Create a Supabase Project
1. Go to [https://supabase.com](https://supabase.com) and sign in.
2. Click **New project**, choose an organization and project name (e.g. `taskflow-prod`).
3. Set a database password and select your region.

### Step 2: Run the SQL Migration
Open the **SQL Editor** in your Supabase Dashboard, create a new query, and run the following script (also found in `/supabase/migrations/20261105000000_create_tasks_table.sql`):

```sql
-- Enable UUID extension if needed
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- Create Tasks table
CREATE TABLE IF NOT EXISTS public.tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    title TEXT NOT NULL CHECK (char_length(trim(title)) > 0),
    description TEXT DEFAULT '',
    priority TEXT NOT NULL DEFAULT 'MEDIUM' CHECK (priority IN ('HIGH', 'MEDIUM', 'LOW')),
    category TEXT NOT NULL DEFAULT 'Work' CHECK (category IN ('Work', 'Personal', 'Study', 'Projects')),
    due_date TIMESTAMPTZ,
    completed BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Automatic updated_at trigger
CREATE OR REPLACE FUNCTION public.handle_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trigger_tasks_updated_at ON public.tasks;
CREATE TRIGGER trigger_tasks_updated_at
    BEFORE UPDATE ON public.tasks
    FOR EACH ROW
    EXECUTE FUNCTION public.handle_updated_at();

-- Database Indexes for high performance querying
CREATE INDEX IF NOT EXISTS idx_tasks_user_id ON public.tasks(user_id);
CREATE INDEX IF NOT EXISTS idx_tasks_user_due_date ON public.tasks(user_id, due_date);
CREATE INDEX IF NOT EXISTS idx_tasks_user_completed ON public.tasks(user_id, completed);
CREATE INDEX IF NOT EXISTS idx_tasks_user_priority ON public.tasks(user_id, priority);
CREATE INDEX IF NOT EXISTS idx_tasks_user_category ON public.tasks(user_id, category);

-- Enable Row Level Security (RLS)
ALTER TABLE public.tasks ENABLE ROW LEVEL SECURITY;

-- 1. Read Policy: Users can only see their own tasks
CREATE POLICY "Users can view their own tasks"
    ON public.tasks FOR SELECT TO authenticated
    USING (auth.uid() = user_id);

-- 2. Insert Policy: Users can only insert tasks for themselves
CREATE POLICY "Users can insert their own tasks"
    ON public.tasks FOR INSERT TO authenticated
    WITH CHECK (auth.uid() = user_id);

-- 3. Update Policy: Users can only update their own tasks
CREATE POLICY "Users can update their own tasks"
    ON public.tasks FOR UPDATE TO authenticated
    USING (auth.uid() = user_id)
    WITH CHECK (auth.uid() = user_id);

-- 4. Delete Policy: Users can only delete their own tasks
CREATE POLICY "Users can delete their own tasks"
    ON public.tasks FOR DELETE TO authenticated
    USING (auth.uid() = user_id);
```

### Step 3: Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
VITE_SUPABASE_URL="https://your-project.supabase.co"
VITE_SUPABASE_ANON_KEY="your-anon-public-api-key"
```
You can also connect directly from within the app by clicking the **Database** button in the sidebar or under **Settings > Supabase PostgreSQL**.

---

## 3. Row Level Security (RLS) Guarantees
- Each authenticated user gets a UUID generated by Supabase Auth (`auth.uid()`).
- All database queries for `tasks` strictly check `auth.uid() = user_id`.
- Users cannot read, modify, or delete tasks belonging to other accounts.
- Service-role secret keys are never exposed in client code.

---

## 4. Vercel Deployment

1. Push this repository to GitHub or GitLab.
2. In [Vercel](https://vercel.com), click **Add New Project** and import the repository.
3. In Project Settings, set Environment Variables:
   - `VITE_SUPABASE_URL` = `https://your-project.supabase.co`
   - `VITE_SUPABASE_ANON_KEY` = `your-anon-key`
4. Build command: `npm run build`
5. Output directory: `dist`
6. Click **Deploy**.
